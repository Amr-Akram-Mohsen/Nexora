You are working on a Flask project with a strict layered architecture.

You MUST follow these rules:

1. Routes (api/ or web/) MUST NOT:
   - Access database models directly
   - Contain business logic
   - Call domains directly
   → They ONLY call application layer

2. Application layer:
   - Orchestrates multiple domains
   - Can call domain services
   - Contains workflows (feed, catalog, ranking, etc.)
   - MUST NOT use Flask globals (request, current_user)

3. Domains:
   - Pure business logic only
   - No Flask, no request, no templates
   - No cross-domain imports (use application layer instead)

4. Presentation (context/):
   - Handles template context only
   - Can call application layer
   - Can use Flask (request, current_user)

5. Shared:
   - Only generic utilities (no domain logic)

6. Integrations:
   - External APIs only
   - Never used directly by routes

When modifying files:
- Respect boundaries strictly
- If logic is misplaced, MOVE it to correct layer
- Prefer creating new files over overloading existing ones

Your goal is to IMPROVE structure, not just make code work.
